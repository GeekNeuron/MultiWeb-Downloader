# MultiWeb Downloader

مدیر دانلود چندگانه، با رابطی نزدیک به نرم‌افزارهای دانلود منیجر (تولبار، سایدبار فیلتر، لیست جدولی، نوار وضعیت) — برای پوشه/فایل گیت‌هاب، لینک مستقیم هر فایلی، و لینک‌های کشف‌شده در یک صفحه‌ی وب.

هیچ فایلی روی سروری میزبانی نمی‌شود، هیچ مرحله‌ی بیلدی لازم نیست — سه فایل ساده‌اند که مستقیم در مرورگر اجرا می‌شوند.

## اجرا

```
python3 -m http.server 8000
# یا هر سرور استاتیک دیگر
```
و `index.html` را باز کنید. برای انتشار عمومی همین سه فایل را روی GitHub Pages یا هر هاست استاتیک دیگری بگذارید.

## قابلیت‌ها

**هسته‌ی دانلود (حفظ‌شده از پروژه‌ی اصلی، با چند اصلاح):**
- پوشه‌ی گیت‌هاب → از Trees API لیست می‌شود؛ برای مخزن‌های بزرگ (truncated) به Contents API با **گشت هم‌زمان روی زیرپوشه‌ها** (نه یکی‌یکی) برمی‌گردد — سریع‌تر از نسخه‌ی قبلی همین ابزار.
- فایل تکی گیت‌هاب (`blob/…`) — نسخه‌ی اصلی فقط `tree/` را می‌فهمید.
- کل مخزن، با `fetch` + هدر توکن (نه ناوبری صفحه‌ای مثل نسخه‌ی اصلی) — پیشرفت واقعی نشان می‌دهد و برای ریپوی خصوصی هم کار می‌کند.
- تشخیص Git LFS، فیلتر ایمنیِ نام‌فایل مشکوک (malware/virus/trojan)، توکن اختیاری در localStorage.

**مدیریت صف (رابط شبیه دانلود منیجر):**
- افزودن چند لینک هم‌زمان از یک دیالوگ، یا **یک‌کلیکی مستقیم از کلیپبورد** («افزودن از کلیپبورد» در تولبار — همه‌ی لینک‌های کپی‌شده را می‌خواند و مستقیم به صف اضافه می‌کند، بدون باز کردن دیالوگ).
- **Pause/Resume واقعی** — نه لغو-و-شروع‌دوباره: دانلود بین فایل‌ها (برای پوشه) یا بین تکه‌های جریان بایتی (برای فایل تکی/کل‌مخزن) مکث می‌کند و از همان‌جا ادامه می‌دهد، بدون از دست رفتن پیشرفت.
- **سرعت و زمان تقریبی باقی‌مانده** برای هر مورد، محاسبه‌شده زنده از نرخ دریافت داده.
- **سایدبار فیلتر** (همه / در حال دانلود / در صف / تمام‌شده / خطا) با شمارنده، و **نوار وضعیت** پایین صفحه با خلاصه‌ی کل صف.
- حالت **«ادغام در یک بسته»**: پوشه‌ها، فایل‌های تکی، کل مخزن‌ها، حتی عکس‌فوری صفحه‌ها — همه در یک ZIP مشترک.
- **دانلود صفحه‌ی وب**: اسکن لینک‌های صفحه، انتخاب چندتایی، افزودن به صف با یک کلیک؛ یا ذخیره‌ی خودِ صفحه به‌صورت HTML.
- **Import/Export صف** به JSON (در تنظیمات) — برای پشتیبان‌گیری یا اشتراک‌گذاری یک لیست دانلود.
- سازگار با پارامترهای URL نسخه‌ی اصلی (`?url=`, `?filename=`) و پارامتر جدید `?urls=` برای یک لینکِ اشتراکیِ چندموردی.

## پوشه‌ی extras/

دو تکمیلِ اختیاری که مستقیماً به کمبودهای گزارش‌شده‌ی قبلی پاسخ می‌دهند:

- **`extras/cors-proxy-worker.js` + `wrangler.toml`** — یک پراکسی CORS آماده برای Cloudflare Workers. دیپلوی با:
  ```
  cd extras && npx wrangler login && npx wrangler deploy
  ```
  آدرسی که چاپ می‌شود را (با `?url=` در انتها) در تنظیمات برنامه در فیلد «پراکسی CORS سفارشی» بگذارید. **فقط روی حساب Cloudflare خودتان دیپلویش کنید** — هر پراکسی‌ای که استفاده کنید، به لینک‌های عبوری از آن دسترسی دارد؛ کد این پراکسی چیزی لاگ یا ذخیره نمی‌کند، ولی این تضمین فقط برای نسخه‌ای معتبر است که خودتان دیپلوی کرده‌اید.

- **`extras/extension/`** — یک افزونه‌ی مینیمال (Manifest V3، Chrome/Edge/Firefox) که روی صفحه‌ی هر پوشه/فایل گیت‌هاب یک دکمه‌ی «افزودن به MultiWeb Downloader» می‌گذارد که در تب جدید ابزار را با `?url=` همان صفحه باز می‌کند. آدرس ابزار میزبانی‌شده‌ی خودتان را یک‌بار در تنظیمات افزونه (آیکن افزونه → گزینه‌ها) وارد کنید. نصب دستی: `chrome://extensions` → حالت توسعه‌دهنده → «Load unpacked» → پوشه‌ی `extras/extension`.

## محدودیت‌های شناخته‌شده (به‌روزشده)

موارد زیر همچنان واقعی‌اند — بعضی محدودیتِ خودِ مرورگر است، نه چیزی که کد بهتر حلش کند:

1. **CORS برای صفحه‌ها/فایل‌های غیرگیت‌هابی.** بدون پراکسی، خیلی از سایت‌ها با «مسدود (CORS)» مواجه می‌شوند. پراکسی Worker بالا این را برای هر سایتی حل می‌کند، ولی نیاز به دیپلوی دارد (رایگان است، ولی یک قدم اضافه).
2. **خواندن کلیپبورد به Context امن نیاز دارد.** روی `file://` یا سایت بدون HTTPS، دکمه‌ی «افزودن از کلیپبورد» کار نمی‌کند (خودِ برنامه این حالت را تشخیص می‌دهد و دکمه را مخفی می‌کند). راه‌حل: از یک سرور استاتیک با HTTPS (یا حتی `localhost`) استفاده کنید.
3. **Pause فقط در همان تب/نشست کار می‌کند.** چیزی روی دیسک نیمه‌کاره ذخیره نمی‌شود؛ اگر تب را ببندید، پیشرفتِ موردهای متوقف‌شده از بین می‌رود (چون کل پردازش در حافظه‌ی جاوااسکریپت است، نه یک دانلود resumable واقعی در سطح فایل‌سیستم).
4. **حالت ادغام برای چند مخزن بزرگ همچنان حافظه‌بر است.** چون JSZip همه‌چیز را در RAM نگه می‌دارد تا ZIP نهایی ساخته شود. **فشرده‌سازی جریانی (streaming zip)** — که این محدودیت را واقعاً حل می‌کند — عمداً در این نسخه پیاده نشد: نیاز به کتابخانه‌ای غیر از JSZip (مثل `client-zip`) و در بهترین حالت File System Access API دارد که فقط Chrome/Edge پشتیبانی می‌کنند (نه Firefox/Safari)، و چون امکان تست در مرورگر واقعی در این محیط نبود، ترجیح دادم به‌جای کد نیمه‌تست‌شده، این را صادقانه به‌عنوان کار باقی‌مانده گزارش کنم.
5. **بدون تست خودکار در مرورگر واقعی.** منطق خالص (تشخیص نوع لینک، تجزیه‌ی مسیر گیت‌هاب) با اسکریپت جدا در Node تأیید شد؛ ساختار HTML/CSS به‌صورت خودکار برای تعادل تگ/براکت و کنتراست رنگ (WCAG AA) بررسی شد؛ ولی رندر واقعی و مسیرهای شبکه‌ی زنده را نمی‌توانم اینجا با چشم خودم تأیید کنم.
6. **افزونه‌ی مرورگر پایه است، نه محصول کامل.** فقط یک دکمه اضافه می‌کند؛ آیکن ندارد (برای سادگی)، و به یک نمونه‌ی از قبل هاست‌شده از خودِ ابزار نیاز دارد (آدرس را در تنظیماتش وارد می‌کنید).
